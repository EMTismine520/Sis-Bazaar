# 肥鹅美食街风格合成小游戏

这是一个移动端竖屏美食合成小游戏，包含使用手绘素材的独立网页版本和 Python + Pygame-ce 原型。当前网页版本为 **v2.0.0**；本次更新不改变 Pygame 版本。

## 在线试玩

网页版本已配置 GitHub Pages 自动部署，发布地址为：

<https://emtismine520.github.io/Sis-Bazaar/>

用手机浏览器打开即可游玩。将相同等级、同类食材拖到一起合成，把食材拖入棋盘第三格的烹饪锅，再点击锅开火。把符合订单要求的棋盘食材或料理拖到上方订单卡完成提交。点击“商店”购买下一等级食材，点击“图鉴”查看发现记录和食谱。

仓库的 `main` 分支每次推送都会通过 GitHub Actions 发布 `web/` 目录。首次启用仓库时，在 GitHub 的 Settings → Pages 中将发布来源设为 GitHub Actions。

## v2.0.0 奖励与成长

新游戏从第 1 天、120 金币开始。蔬菜与肉类两条路线的 Lv.1–Lv.3 初始开放；从 Lv.4 起，分别在商店按顺序解锁，购买只开放合成权限，不直接赠送食材，也不标记为已发现。

| 行为 | 金币变化 |
| --- | --- |
| 成功合成 | +3 |
| 烹饪出锅 | +料理等级 × 3 |
| 提交一份订单目标 | `16 + 订单等级 × 8` |
| 完成整张订单 | 额外 +16 |
| 解锁 Lv.4 及以上食材 | −[60 + (等级 − 4) × 30] |

例如 Lv.4、Lv.5、Lv.6 的解锁价格依次为 60、90、120 金币。金币不足或前一级尚未解锁时无法购买；未购买的等级不能通过合成生成。两条路线分别解锁，互不影响。

订单等级为 `min(8, 1 + floor((天数 - 1) / 2))`，份数为 `min(订单等级, 3)`；完成一张订单才进入下一天。第 1–2 天为 Lv.1 一份，第 3–4 天为 Lv.2 两份，第 5–6 天为 Lv.3 三份，之后每两天升一级，第 15 天起 Lv.8 三份封顶。

路线目标按当天等级生成，不受购买和发现限制；未购买目标显示“需先在商店解锁 Lv.X”，已购买未发现目标显示“合成后提交”。同级已发现锅料理也参与候选，未发现锅料理不会出现。先随机排列不同目标，候选不足时循环补足；当天候选只有两项时，三份订单会让其中一项出现两份。订单生成后固定，购买、合成和刷新页面不会重抽；订单预告只显示下一天等级和份数，展示目标不会增加发现记录。

把匹配目标逐份拖到订单卡，每份提交立即消耗一格并发放 `16 + 等级 × 8` 金币，最后一份额外获得固定 16 金币。错误提交保留食材且不发奖。整单总额为 `份数 × (16 + 等级 × 8) + 16`；Lv.1–Lv.8 按上述节奏依次为 **40、80、136、160、184、208、232、256** 金币。卡片显示每份奖励、完成奖励及剩余可得金币；部分提交不推进天数。

蔬菜包和肉类包仍各有 1000 次，不增加额外补给。Lv.8 一份路线食材需要 128 份基础食材，三份共需 384 份，是高消耗后期挑战；有限资源不保证无限天数游玩。

## 网页存档

网页继续使用 `localStorage` 键 `sis-bazaar-game-v2`，schema 为 2、页面版本为 2.0.0。保存金币、棋盘、订单目标和逐项进度、天数、两类包次数、解锁、发现记录、锅内内容。新增订单规则标识 `daily-v1`，订单保存 `orderRule`、`items`、`submitted`、`level`、`quantity`、`reward`、`perItemReward`、`completionReward`。每次提交后立即保存，刷新恢复已付金币与进度，不会重复领奖。

已有订单保留目标和部分提交进度，标记 `legacy-v2` 并按旧规则完成一次（完成时获得 `16 + 等级 × 8 + (份数 - 1) × 8`，部分提交不发奖），不追补历史奖励；下一单应用新规则。更旧的单目标订单会包装为一份未提交订单。新规则允许未购买/未发现路线目标，棋盘和锅内食材仍必须合法且已解锁。损坏或不兼容存档回退新游戏，弹窗开关状态不保存。

“重新开始”会先要求确认；取消会保留进度，确认后清除旧 v2 存档并保存全新的初始状态。损坏或版本不匹配的存档会初始化新游戏，不迁移旧数据。不同浏览器、设备和站点（包括本地预览与线上）不共享存档；浏览器禁止存储时仍可游玩，但刷新不能保证保留进度。

## 本地运行

在项目根目录 PowerShell 执行：

```powershell
.\.venv\Scripts\Activate.ps1
python -m game.main
```

## 浏览器运行

推荐使用不依赖 WASM/CDN 的快速网页版本：

```powershell
.\.venv\Scripts\Activate.ps1
python serve.py
```

浏览器会自动打开 `http://127.0.0.1:8000/`。这个入口启动很快，适合手机试玩。
如果提示 8000 端口被占用，改用：`python serve.py 8001`，然后打开 `http://127.0.0.1:8001/`。

原 Pygame/pygbag 版本仍可这样运行，但首次启动会下载和编译 WASM，速度较慢：

```powershell
.\.venv\Scripts\Activate.ps1
$env:PYTHONUTF8='1'
python -m pygbag game
```

终端显示本地地址后，用手机或电脑浏览器打开该地址。手机与电脑需要在同一局域网，手机访问电脑的局域网 IP 和终端显示的端口，例如 `http://192.168.1.20:8000/`。

# 肥鹅美食街风格合成小游戏

这是一个移动端竖屏美食合成小游戏，包含使用手绘素材的独立网页版本和 Python + Pygame-ce 原型。当前网页版本为 **v2.0.0**；本次更新不改变 Pygame 版本。

## 在线试玩

网页版本已配置 GitHub Pages 自动部署，发布地址为：

<https://emtismine520.github.io/Sis-Bazaar/>

用手机浏览器打开即可游玩。将相同等级、同类食材拖到一起合成，把食材拖入棋盘第三格的烹饪锅，再点击锅开火。把符合订单要求的棋盘食材或料理拖到上方订单卡完成提交。点击“商店”购买下一等级食材，点击“图鉴”查看发现记录和食谱。

仓库的 `main` 分支每次推送都会通过 GitHub Actions 发布 `web/` 目录。首次启用仓库时，在 GitHub 的 Settings → Pages 中将发布来源设为 GitHub Actions。

## v2.0.0 奖励与成长

新游戏从第 1 天、120 金币开始。蔬菜与肉类两条路线的 Lv.1–Lv.3 初始开放；从 Lv.4 起，分别在商店按顺序解锁，购买只开放合成权限，不直接赠送食材，也不标记为已发现。

| 行为 | 金币变化 |
| --- | --- |
| 成功合成 | +3 |
| 烹饪出锅 | +料理等级 × 3 |
| 提交订单 | +16 + 订单等级 × 8 |
| 解锁 Lv.4 及以上食材 | −[60 + (等级 − 4) × 30] |

例如 Lv.4、Lv.5、Lv.6 的解锁价格依次为 60、90、120 金币。金币不足或前一级尚未解锁时无法购买；未购买的等级不能通过合成生成。两条路线分别解锁，互不影响。

订单只从已经发现且已开放的路线食材、已经发现的锅料理中选择。尚未做出料理时，订单使用已发现的基础食材。提交不匹配的食材会提示需求并保留原格；成功提交会消耗该格食材、发放金币、天数加一并生成下一单。奖励不会额外增加食材包：蔬菜包和肉类包仍各有 1000 次。

## 网页存档

网页使用当前浏览器、当前站点的 `localStorage` 自动保存 v2 进度（键为 `sis-bazaar-game-v2`，schema 为 2）：金币、棋盘、订单、天数、两类包的剩余和开启次数、解锁等级、发现记录以及锅内内容。每次游戏状态变更后保存，刷新页面会恢复。商店与锅弹窗的打开状态不保存。

“重新开始”会先要求确认；取消会保留进度，确认后清除旧 v2 存档并保存全新的初始状态。损坏或版本不匹配的存档会初始化新游戏，不迁移旧数据。不同浏览器、设备和站点（包括本地预览与线上）不共享存档；浏览器禁止存储时仍可游玩，但刷新不能保证保留进度。

## 本地运行

在项目根目录 PowerShell 执行：

```powershell
.\.venv\Scripts\Activate.ps1
python -m game.main
```

## 浏览器运行

推荐使用不依赖 WASM/CDN 的快速网页版本：

```powershell
.\.venv\Scripts\Activate.ps1
python serve.py
```

浏览器会自动打开 `http://127.0.0.1:8000/`。这个入口启动很快，适合手机试玩。
如果提示 8000 端口被占用，改用：`python serve.py 8001`，然后打开 `http://127.0.0.1:8001/`。

原 Pygame/pygbag 版本仍可这样运行，但首次启动会下载和编译 WASM，速度较慢：

```powershell
.\.venv\Scripts\Activate.ps1
$env:PYTHONUTF8='1'
python -m pygbag game
```

终端显示本地地址后，用手机或电脑浏览器打开该地址。手机与电脑需要在同一局域网，手机访问电脑的局域网 IP 和终端显示的端口，例如 `http://192.168.1.20:8000/`。
